## 1. 確認規格與實作前查核

- [ ] 使用者確認 spec 文件的中文案例與第一階段邊界。
- [ ] 讀取實作涉及的專案文件及 scoped instructions。
- [ ] 查核 completedWork 型別、正規化、截斷與來源資料。
- [ ] 確認 Pi 的 prompt 建立入口、共用 renderer 消費者與精確測試指令。
- [ ] 確認設計能保留來源、信任標記與唯一完整正文；不成立時先調整設計。

## 2. 實作（需另行授權）

- [ ] 增加預設關閉的同次摘要去重選項，僅由 Pi 啟用。
- [ ] 以原文字串嚴格相等比較，保留唯一完整正文及必要 metadata。
- [ ] 不改 session、事件游標、資料庫或其他 adapter 行為。

## 3. 測試與量測

- [ ] 中文案例確認後，再撰寫對應測試程式。
- [ ] 驗證 renderer 與 Pi 實際呼叫路徑，不只測 helper。
- [ ] 驗證選項未開啟及非 Pi 的輸出不變。
- [ ] 執行範圍內測試與型別檢查，保留指令、輸出及未通過項目。
- [ ] 固定同一輸入，比較原版／修改版的最終 prompt UTF-8 bytes、正文份數與新事件完整性。
- [ ] 若可取得匿名化 GH-5 輸入，增加離線重播；不可得則明確標示僅使用合成案例。

## 4. 交付與階段門檻

- [ ] 提供變更摘要、驗證輸出、量測表與停用選項的回滾步驟。
- [ ] 明列未驗證情境與 token／費用未量測的限制。
- [ ] 第一階段驗收後，再由使用者決定是否規劃第二階段。
- [ ] 未另行批准，不部署、不修改執行中服務、不自動開始第二階段。
